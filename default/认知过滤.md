这两个概念是你的认知过滤工具（v0.2）在“语义层”的核心指标。简单来说：信息熵衡量“信息含量有多大”，逻辑跳跃度衡量“思维连续性有多差”。两者结合，能精准揪出“又空又玄”或“太密太跳”的文本。

—

1. 信息熵（Information Entropy）

· 本质：衡量信息的不可预测性或惊喜度。熵越高，信息越密集；熵越低，内容越啰嗦、越冗余。
· 在文本中的表现：
  · 低熵：“今天天气很好，阳光明媚，万里无云。”（全是常见词，下一词基本能猜到，信息量极低）。
  · 高熵：“基于拓扑绝缘体的量子反常霍尔效应，在零磁场下实现了无耗散边缘态。”（术语密集，词频分布平均，难以预测，认知负荷极高）。
· 对你的工具价值：设定阈值。熵过低 → 废话太多，直接打回；熵过高 → 可能过于浓缩，标记为“需拆解”，放到后续处理队列。
· 简易计算方法（本地CLI友好）：
  · 字符级熵：统计文本中每个字符（或词汇）出现的概率 p_i，计算 H = -\sum p_i \log_2(p_i)。Python 可用 collections.Counter 极速算出。
  · 压缩比法：用 gzip 压缩文本，压缩后大小 / 原始大小。比值越低（压缩率大），说明原文本冗余度高（熵低）；比值越高，说明随机性强（熵高）。

—

2. 逻辑跳跃度（Logical Jumpiness）

· 本质：衡量句子或段落之间隐含推理链条的断裂程度。跳跃度越高，读者越需要自己脑补“因为……所以……”。
· 在文本中的表现：
  · 低跳跃：“项目延期了。因为服务器宕机了。所以我们需要增加预算买新机器。”（因果连贯，无缝衔接）。
  · 高跳跃：“项目延期了。AI 大模型训练成本下降了。明天下午三点开会。”（三个独立的点强行拼接，读者完全不知道关联，需要极大的工作记忆去猜测）。
· 对你的工具价值：核心打回指标。如果你的日志或文档跳跃度太高，说明你是在“给未来的自己加密”，增加回忆负担。工具应强制打回，并提示你补充过渡句。
· 简易计算方法（本地CLI友好）：
  · 向量余弦法：用本地小模型（如 all-MiniLM-L6-v2）将相邻句子转为向量，计算余弦相似度。相似度极低（<0.3）则判定为高跳跃。
  · 连接词检测法：统计“因为、所以、然而、因此”等逻辑连接词的密度。如果跨段落后没有任何连接词，且主语突变，直接扣分。

1. 为什么代码比文档更容易让你“头疼”？

代码的跳跃度不仅体现在逻辑分支（圈复杂度），更体现在上下文切换成本：

· 变量作用域跨度：一个变量定义在 200 行前，你看到后面时，大脑必须回拽记忆（高跳跃）。
· 嵌套深渊：if -> for -> if -> try 嵌套 5 层，大脑需要维护 5 个栈帧（极高熵 + 高跳跃）。
· 命名熵：data, temp, result 随处可见（低熵但高混淆），加上突然冒出的 userAuthenticationManager（高熵），混在一起直接爆表。

2. 给你的 CLI 增加“头痛指数”（综合评分）

建议将文本和代码统一映射到 0~100 的头痛指数：

· 0~30：轻松愉悦（刷社交媒体水平）
· 30~60：轻度烧脑（正常技术文档）
· 60~80：明显头疼（需要中途喝水休息）
· 80~100：即刻打回，必须拆解或补充桥接

计算公式（草稿）：

```
头痛指数 = (熵分 * 0.4) + (跳跃度 * 0.6) + (嵌套惩罚，仅代码)
```

跳跃度权重更高，因为断裂感比密度更消耗精力。

3. 直接可用的“代码头痛”检测片段（Python）

结合 radon（圈复杂度）和 ast（嵌套深度），写一个本地检测函数：

```python
import ast
import radon.complexity as rc

def code_headache_score(filepath):
    with open(filepath) as f:
        tree = ast.parse(f.read())
    
    # 1. 最大嵌套深度（惩罚项）
    max_depth = 0
    for node in ast.walk(tree):
        if isinstance(node, (ast.If, ast.For, ast.While, ast.Try, ast.With)):
            depth = sum(1 for _ in node.iter_child_nodes()) # 简化示意
            max_depth = max(max_depth, depth)
    
    # 2. 圈复杂度（用 radon 取最大值）
    complexity = max([block.complexity for block in rc.cc_visit(filepath)], default=1)
    
    # 3. 命名熵（统计变量名的多样性，越高越抽象）
    names = [node.id for node in ast.walk(tree) if isinstance(node, ast.Name)]
    entropy = -sum((names.count(n)/len(names)) * log2(names.count(n)/len(names)) for n in set(names)) if names else 0
    
    # 综合得分（权重可调）
    score = (entropy * 0.3) + (complexity * 0.3) + (max_depth * 0.4)
    return min(score, 100)  # 归一化
```

重点：当你 cog check 一个 .py 文件时，如果 max_depth > 4，直接抛出 “嵌套地狱，建议拆函数”。

4. 针对文本的“跳跃度”精准打击（连接词缺失惩罚）

对你之前的日志，建议增加强制连接词检测：

```python
def jumpiness(text):
    sentences = text.split(’。‘)
    if len(sentences) < 2: return 0.0
    
    bridges = [’因为‘,’所以‘,’然而‘,’因此‘,’基于‘,’例如‘,’但是‘,’那么‘]
    no_bridge_count = 0
    for i in range(len(sentences)-1):
        # 检查后一句是否以桥接词开头
        if not any(sentences[i+1].strip().startswith(b) for b in bridges):
            no_bridge_count += 1
    
    ratio = no_bridge_count / (len(sentences) - 1)
    return min(ratio, 1.0)  # 0.7 以上即视为高跳跃
```
